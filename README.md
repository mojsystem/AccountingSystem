# AccountingSystem

سیستم حسابداری و خرید/فروش ارز برای صرافی، با **C# و .NET 8.0** و **SQL Server 2016**.
برنامه به‌صورت **وب** (ASP.NET Core Razor Pages) و **ویندوز** (Windows Forms) اجرا می‌شود و هر دو از یک هسته‌ی مشترک و یک پایگاه داده استفاده می‌کنند.

## امکانات

- خرید ارز از مشتری و فروش ارز به مشتری، با ثبت نام مشتری و کد ملی (اختیاری)
- قیمت تمام‌شده‌ی ارز به روش **میانگین موزون** و محاسبه‌ی سود/زیان تحقق‌یافته هر فروش
- صندوق ریال و صندوق جدا برای هر ارز؛ موجودی منفی ثبت نمی‌شود
- نرخ خرید و فروش روز برای هر ارز، همراه با تاریخچه
- سند حسابداری دوطرفه برای هر معامله؛ هر سند قبل از ثبت بررسی تراز می‌شود
- موجودی افتتاحیه ریال و ارز
- داشبورد: موجودی صندوق‌ها، ارزش روز موجودی ارزی، سود/زیان شناور و معاملات امروز
- کاربران با دو نقش **مدیر** (دسترسی کامل) و **کاربر صندوق** (ثبت معامله و نرخ)؛ رمز عبور با PBKDF2
- نمایش تاریخ به تقویم شمسی

## ساختار پروژه

| مسیر | توضیح |
|---|---|
| `database/AccountingSystem.sql` | اسکریپت ایجاد پایگاه داده، جدول‌ها و داده‌ی اولیه (سازگار با SQL Server 2016) |
| `src/AccountingSystem.Core` | منطق خالص: محاسبه‌ی معامله، سند حسابداری، سرویس‌ها، هش رمز، تبدیل ارقام فارسی |
| `src/AccountingSystem.Data` | پیاده‌سازی ذخیره‌سازی با `Microsoft.Data.SqlClient` و تراکنش SQL |
| `src/AccountingSystem.Web` | نسخه‌ی وب (Razor Pages، ورود با کوکی، نقش‌ها) |
| `src/AccountingSystem.WinForms` | نسخه‌ی ویندوز (فرم‌ها و تب‌ها، همان سرویس‌های هسته) |

## راه‌اندازی

### ۱. ایجاد پایگاه داده

با کاربری که دسترسی `sysadmin` دارد اجرا کنید (فقط یک‌بار):

```bat
sqlcmd -S localhost -E -f 65001 -i database\AccountingSystem.sql
```

یا فایل را در SSMS باز و Execute کنید. اسکریپت پایگاه داده‌ی `AccountingSystem` را با سطح سازگاری ۱۳۰ (SQL Server 2016) می‌سازد.

### ۲. تنظیم رشته‌ی اتصال

رشته‌ی اتصال را در این فایل‌ها تنظیم کنید:

- `src/AccountingSystem.Web/appsettings.json` ← بخش `ConnectionStrings:AccountingSystem`
- `src/AccountingSystem.WinForms/appsettings.json` ← همین بخش

### ۳. اجرای نسخه‌ی وب

برای توسعه و اجرای محلی:

```bash
dotnet run --project src/AccountingSystem.Web
```

برای اجرای روی سرور (محیط Production، همان خروجی `publish`):

```bash
dotnet publish src/AccountingSystem.Web -c Release -o publish/web
cd publish/web
dotnet AccountingSystem.Web.dll
```

آدرس پیش‌فرض: `http://localhost:5080` (در `appsettings.json` به `0.0.0.0` متصل است تا از شبکه‌ی داخلی هم در دسترس باشد).

- اگر هیچ کاربری ثبت نشده باشد، صفحه‌ی **راه‌اندازی اولیه** نمایش داده می‌شود و اولین کاربر، مدیر سیستم خواهد بود.
- برای دسترسی از اینترنت یا شبکه‌ی ناامن، برنامه را پشت یک Reverse Proxy با HTTPS قرار دهید.

### ۴. اجرای نسخه‌ی ویندوز

```bat
dotnet run --project src/AccountingSystem.WinForms
```

(یا فایل `AccountingSystem.exe` پس از `dotnet publish`). فایل `appsettings.json` باید کنار فایل اجرایی باشد.

## منطق حسابداری

حساب‌ها: `1001` صندوق ریال، `1101-<کد ارز>` موجودی ارز به بهای تمام‌شده، `3001` سرمایه‌ی افتتاحیه، `4001` سود معاملات ارزی، `5001` زیان معاملات ارزی.

| رویداد | سند |
|---|---|
| خرید ارز از مشتری | بدهکار `1101-X` (بهای ریالی) / بستانکار `1001` |
| فروش ارز به مشتری | بدهکار `1001` (مبلغ ریالی) / بستانکار `1101-X` (بهای تمام‌شده) و `4001` یا بدهکار `5001` برای تفاوت |
| موجودی افتتاحیه ارز | بدهکار `1101-X` / بستانکار `3001` |

- مبلغ ریالی هر معامله = مقدار × نرخ، به نزدیک‌ترین ریال (نیم به دور از صفر) گرد می‌شود.
- بهای تمام‌شده‌ی مقدار فروخته‌شده = موجودی بهای تمام‌شده × مقدار فروش ÷ موجودی ارز. فروش کل موجودی، دقیقاً کل بهای ثبت‌شده را خارج می‌کند.
- هر معامله در **یک تراکنش** SQL ثبت می‌شود. اگر موجودی صندوق یا بهای تمام‌شده هم‌زمان توسط کاربر دیگری تغییر کرده باشد، تراکنش لغو و پیام «اطلاعات در همین لحظه توسط کاربر دیگری تغییر کرده است. لطفاً دوباره تلاش کنید.» نمایش داده می‌شود.

## تست‌ها

```bash
dotnet test tests/AccountingSystem.Core.Tests
```

برای تست‌های یکپارچگی روی SQL Server، رشته‌ی اتصال (با دسترسی ساخت پایگاه داده) را در متغیر `AS_TEST_SQL` قرار دهید. تست‌ها پایگاه داده‌ی `AccountingSystem_IT` را از روی همان اسکریپت می‌سازند و اگر این متغیر تنظیم نشده باشد، بدون خطا رد می‌شوند.

```bash
set AS_TEST_SQL=Server=localhost;User Id=sa;Password=...;Encrypt=False;TrustServerCertificate=True
dotnet test tests/AccountingSystem.Data.Tests
```

در CI (`.github/workflows/ci.yml`) علاوه بر تست‌ها، برنامه‌ی وب پس از `publish` اجرا می‌شود و با `.github/scripts/web-smoke.py` بررسی می‌شود که ورود مدیر انجام شود، فایل‌های استاتیک سرو شوند و صفحات اصلی و صفحه‌ی کاربران (فقط مدیر) باز شوند.

## سازگاری با SQL Server 2016

- فقط از امکانات موجود در SQL Server 2016 استفاده شده است (بدون JSON-native، temporal یا graph).
- سطح سازگاری دیتابیس ۱۳۰ تنظیم می‌شود.
- در CI، تست‌های یکپارچگی روی **SQL Server 2019** (با سطح سازگاری ۱۳۰) اجرا می‌شوند؛ موتور SQL Server 2016 در CI در دسترس نیست. پیش از استقرار، یک‌بار روی SQL Server 2016 واقعی اجرای اسکریپت و تست‌های `AS_TEST_SQL` را انجام دهید.

## محدودیت‌ها و کارهای باقی‌مانده

- ابطال معامله در این نسخه پیاده‌سازی نشده است؛ اصلاح باید با سند اصلاحی انجام شود.
- کارمزد معامله، چاپ رسید و خروجی Excel در این نسخه نیستند.
- ورود تاریخ به‌صورت شمسی نیست؛ نمایش تاریخ شمسی است.
- چند شعبه پشتیبانی نمی‌شود.
- الزامات قانونی شناسایی مشتری (احراز هویت، گزارش به مراجع ذی‌ربط) باید با مشاور حقوقی بررسی شود؛ این نرم‌افزار جایگزین آن‌ها نیست.
- نسخه‌ی Windows Forms فقط روی ویندوز اجرا می‌شود و در CI فقط کامپایل می‌شود.
